Como a web funciona

Antes de falar de PWA, vamos entender o que acontece quando você abre um site. Você não precisa saber nada de programação para começar: este curso parte do zero.

O que você vai aprender neste módulo

  • O que são navegador, servidor e endereço de site.
  • O que são HTML, CSS e JavaScript, e para que cada um serve.
  • Como espiar o código de qualquer site.

Quando aparecer uma palavra difícil, explicamos na hora, e há um glossário no fim do menu.

Internet e web não são a mesma coisa

As pessoas usam as duas palavras como se fossem iguais, mas são diferentes:

  • Internet é a rede gigante que liga milhões de computadores e celulares do mundo todo, por cabos, antenas e satélites. Pense nela como as estradas.
  • Web (ou "WWW") é um dos serviços que andam por essas estradas: o conjunto de páginas e aplicativos que você abre no navegador, ligados por links. Pense nela como os veículos que circulam pelas estradas.

O WhatsApp e o e-mail também usam a internet, mas não são "a web".

Navegador, site e servidor

Quando você digita um endereço e aperta Enter, acontece uma conversa entre dois computadores:

  • NavegadorO programa que você usa para ver sites, como Chrome, Edge, Firefox ou Safari. Ele é o "cliente" que faz os pedidos.
  • ServidorUm computador sempre ligado, em algum lugar do mundo, que guarda os arquivos do site e os entrega a quem pedir.
  • SiteO conjunto de arquivos (textos, imagens, estilos, códigos) que o servidor entrega e o navegador monta na sua tela.
🏠 Analogia: o restaurante Você é o cliente (navegador). A cozinha é o servidor. O garçom que leva o pedido e traz a comida é a internet. O pedido é a requisição, e o prato que chega é a resposta: os arquivos do site. Guarde essa história, porque vamos usá-la de novo no módulo do Service Worker.

O endereço de um site (URL)

O endereço completo de uma página se chama URL. Veja as partes de um exemplo:

https://pwabrasil.exemplo.com.br/aula/modulo-1.html

https://                   → o "protocolo": a forma segura de conversar
pwabrasil.exemplo.com.br   → o domínio: o "nome" do servidor
/aula/modulo-1.html        → o caminho: qual arquivo você quer, dentro do site

HTTP e HTTPS: o cadeado

HTTP é a "língua" que navegador e servidor falam entre si. O HTTPS é a mesma língua, mas com a conversa embaralhada (criptografada), de modo que ninguém no meio do caminho consegue ler o que você envia ou recebe, como senhas e dados de cartão. É por isso que aparece um cadeado ao lado do endereço.

⚠️ Por que isso importa para PWA? Os recursos mais poderosos de um PWA só funcionam em sites com HTTPS. A única exceção é o endereço localhost, que significa "o meu próprio computador" e serve para testar enquanto você desenvolve.

Um site é feito de arquivos

Um arquivo é um conteúdo guardado com um nome, como uma foto ou um documento. Uma pasta agrupa arquivos. O final do nome, depois do ponto, é a extensão, e ela diz que tipo de arquivo é. Estes são os que vamos usar:

ExtensãoO que éPapel no site
.htmlTexto com marcaçõesO conteúdo e a estrutura da página
.cssTexto com regras de aparênciaCores, tamanhos e posições
.jsTexto com instruçõesO comportamento: o que acontece ao clicar
.json / .webmanifestTexto com dados organizadosInformações de configuração (veremos no Módulo 3)
.png / .svgImagemLogotipos e ícones

Todos os arquivos de código são texto puro. Para escrevê-los você só precisa de um editor de texto. O Bloco de Notas já serve, e o Visual Studio Code (gratuito) deixa tudo mais confortável, com cores e ajuda ao digitar.

As três linguagens da web

Todo site é construído com três linguagens que trabalham juntas.

🏠 Analogia: a construção de uma casa O HTML é a estrutura: paredes, portas e cômodos. O CSS é o acabamento: a cor da tinta, o piso, o tamanho das janelas. O JavaScript é a parte elétrica e hidráulica: faz a luz acender quando você aperta o interruptor.

1) HTML: a estrutura

O HTML não é bem uma "linguagem de programação": é uma linguagem de marcação. Você marca cada pedaço do texto para dizer o que ele é (título, parágrafo, botão). Essas marcações se chamam tags e vêm entre os sinais < e >. Quase sempre há uma tag que abre e outra que fecha (com uma barra).

<!DOCTYPE html>
<html lang="pt-BR">               <!-- tudo fica dentro desta tag; lang = idioma da página -->
  <head>                           <!-- "bastidores": informações que não aparecem na tela -->
    <meta charset="utf-8">         <!-- permite usar acentos: ç, ã, é -->
    <title>Minha página</title>   <!-- o texto que aparece na aba do navegador -->
  </head>
  <body>                           <!-- tudo o que aparece na tela -->
    <h1>Olá, mundo!</h1>          <!-- h1 = título principal -->
    <p>Este é um parágrafo.</p>    <!-- p = parágrafo -->
    <button>Clique aqui</button>  <!-- botão -->
  </body>
</html>

Repare que as linhas entre <!-- e --> são comentários: anotações para humanos, que o navegador ignora.

2) CSS: a aparência

O CSS é um conjunto de regras no formato "escolha este elemento e mude estas características".

h1 {                      /* escolhe todos os títulos h1 */
  color: darkblue;        /* a cor do texto vira azul-escuro */
  font-size: 32px;        /* o tamanho da letra vira 32 pixels */
}

3) JavaScript: o comportamento

O JavaScript é uma linguagem de programação: você escreve instruções, e o navegador as executa na ordem.

// "const" cria uma caixinha com nome, para guardar algo.
// Aqui guardamos o botão da página na caixinha chamada "botao".
const botao = document.querySelector('button');

// "Quando alguém clicar no botão, faça o que está entre as chaves."
botao.addEventListener('click', () => {
  alert('Você clicou!');   // mostra um aviso na tela
});

Módulo 2 de 7

O que é um PWA

Um PWA é um site comum que aprendeu três truques: ser instalado como aplicativo, funcionar sem internet e se comportar como app.

O que você vai aprender neste módulo
  • O problema que os PWAs resolvem.
  • O que significa a sigla PWA.
  • As três peças que todo PWA precisa ter.
  • Quando um PWA é a melhor escolha e quais são os seus limites.

O problema

Imagine que você tem uma ideia de aplicativo. Há dois caminhos tradicionais:

  • Site comum: fácil de publicar e funciona em qualquer aparelho, mas não tem ícone na tela inicial, depende de internet e "parece" um site.
  • Aplicativo nativo (da loja de aplicativos): tem ícone, funciona offline e usa recursos do aparelho, mas é preciso criar uma versão para cada sistema (Android, iPhone, computador), passar pela aprovação da loja e fazer o usuário baixar e atualizar.

O PWA nasceu para dar um meio-termo: um único código, feito com as tecnologias do Módulo 1, que o usuário pode instalar e usar como aplicativo.

O que significa PWA?

PWA é a sigla de Progressive Web App, em português, Aplicativo Web Progressivo.

  • Web App: é feito com tecnologias da web (HTML, CSS e JavaScript).
  • Progressivo: funciona em qualquer navegador, e quanto mais moderno o aparelho, mais recursos ele ganha. Ninguém fica de fora.

As três peças de um PWA

Para virar PWA, um site precisa de três coisas:

  • 1. HTTPSA conexão segura, com cadeado. Sem ela, o navegador não libera os recursos de PWA.
  • 2. ManifestUm arquivo que descreve o app: nome, ícone, cores e como ele deve abrir. É a "ficha de cadastro".
  • 3. Service WorkerUm script que fica entre o app e a internet e decide o que guardar para usar offline. É o "porteiro".
🏠 Analogia: abrir uma lojinha O HTTPS é a porta com fechadura, que dá segurança. O manifest é a placa e o cartão de visita, que dizem o nome e a cara da loja. O Service Worker é o gerente do estoque, que guarda mercadoria nos fundos para que a loja continue vendendo mesmo se o fornecedor atrasar.

PWA × site tradicional × app nativo

CritérioSite tradicionalPWAApp nativo
Ícone na tela inicialNãoSim, sem passar por lojaSim, via loja

⚠️ Limites (é importante saber) Os PWAs não fazem tudo: o iPhone aceita menos recursos do que o Android, e alguns acessos ao hardware (como certos sensores e funções profundas do sistema) ainda são exclusivos de apps nativos. Para a maioria dos serviços do dia a dia, como cursos, listas, agendas e lojas, o PWA é mais que suficiente.

O esqueleto mínimo de um PWA

Só para você ver como é pouco, estas são as duas linhas que "ligam" as peças à página. Nos próximos módulos você entenderá cada uma:

<!-- 1) Aponta para a "ficha de cadastro" do app (manifest) -->
<link rel="manifest" href="manifest.webmanifest">

<script>
  // 2) Contrata o "porteiro" (Service Worker), se o navegador souber trabalhar com ele
  if ('serviceWorker' in navigator) {
    navigator.serviceWorker.register('./sw.js');
  }
</script>

Módulo 3 de 7

Manifest e instalação

O manifest é a ficha de cadastro do seu app. É ele que diz ao celular como o app se chama, qual é o seu ícone e como deve abrir.

O que você vai aprender neste módulo
  • O que é um arquivo JSON e como lê-lo.
  • Para que serve cada campo do manifest.
  • Como instalar um PWA em cada aparelho.
  • Como o código sabe que o app pode ser instalado.

Antes: o que é JSON?

O manifest é escrito em JSON, um jeito de organizar informações em texto. Funciona como um formulário preenchido: cada campo tem um nome (chamado chave) e um valor.

{
  "nome": "Ana",
  "idade": 30,
  "gosta_de": ["café", "música"]
}

Regras básicas, que você vai ver o tempo todo:

  • Tudo fica entre chaves { }.
  • Chave e valor são separados por dois-pontos: "nome": "Ana".
  • Textos ficam entre aspas duplas; números não têm aspas.
  • Uma lista fica entre colchetes [ ], com itens separados por vírgula.
  • Vírgula entre os pares, mas não depois do último. Esquecer isso é o erro mais comum.

O que é o manifest

O manifest é um arquivo (aqui chamado manifest.webmanifest) com o JSON que descreve o app. A página o encontra por esta linha no <head> do HTML:

<link rel="manifest" href="manifest.webmanifest">

Os campos mais importantes

name e short_name
O nome completo e o nome curto. O curto aparece embaixo do ícone na tela inicial, onde o espaço é pequeno.
start_url
A página que abre quando você toca no ícone do app instalado. Normalmente é a página inicial.
scope (escopo)
A "área" do app. Links para dentro dessa área abrem no app; links para fora abrem no navegador comum.
display
Como o app aparece. standalone esconde a barra de endereços do navegador, e o app fica com cara de aplicativo de verdade. Outras opções: browser (aba comum), minimal-ui e fullscreen (tela cheia, comum em jogos).
icons
Uma lista de imagens do ícone em vários tamanhos. O celular escolhe o que melhor se encaixa. O mínimo recomendado é 192×192 e 512×512 pixels.
purpose: "maskable"
Alguns celulares recortam o ícone em círculo ou quadrado arredondado. Se o desenho for até a borda, perde pedaço. Um ícone maskable deixa uma margem de segurança: o desenho importante fica no centro (cerca de 80% da imagem), e o resto é só fundo.
theme_color e background_color
A cor da barra superior do app e a cor da tela de abertura (aquele fundo que aparece enquanto o app carrega).
lang
O idioma do app. Para nós, pt-BR.

O manifest do PWA Brasil (trecho)

{
  "name": "PWA Brasil (PT-BR)",
  "short_name": "PWA Brasil",
  "start_url": "./index.html?source=pwa",
  "scope": "./",
  "display": "standalone",
  "icons": [
    { "src": "icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "icon-maskable-512.png", "sizes": "512x512",
      "type": "image/png", "purpose": "maskable" }
  ]
}
⚠️ JSON não aceita comentários Por isso o bloco acima está sem explicações dentro. Se você escrever comentários num arquivo JSON, o manifest fica inválido e o navegador o ignora. Use o laboratório mais abaixo para conferir o seu.

Como instalar um PWA

Instalar significa colocar o ícone do app na tela inicial ou na lista de programas, para abri-lo como qualquer aplicativo. O caminho depende do aparelho:

  • Chrome no Android: menu ⋮ (três pontinhos) → Instalar app (ou Adicionar à tela inicial).
  • Chrome e Edge no computador: clique no ícone de instalar, na ponta direita da barra de endereços.
  • Safari no iPhone/iPad: botão Compartilhar → Adicionar à Tela de Início.

Os navegadores baseados em Chrome também deixam o seu código oferecer um botão "Instalar" dentro da própria página. É isso que fazemos no laboratório.

Como o código descobre que dá para instalar

Um evento é um aviso que o navegador dá ao seu código quando algo acontece (um clique, a internet que caiu, uma instalação que ficou possível). O código "fica de ouvido": "quando acontecer tal coisa, faça isto".

let eventoInstalacao = null;   // uma caixinha vazia, para guardar o aviso

// "Quando o navegador avisar que o app PODE ser instalado..."
window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();          // não mostre o aviso padrão agora
  eventoInstalacao = e;        // guarde o aviso para usar depois
  botaoInstalar.disabled = false;   // libera o nosso botão
});

// "Quando a pessoa clicar no nosso botão..."
botaoInstalar.addEventListener('click', async () => {
  eventoInstalacao.prompt();   // mostra a janela de instalação do navegador
  const { outcome } = await eventoInstalacao.userChoice;   // espera a resposta:
  // outcome vale 'accepted' (aceitou) ou 'dismissed' (recusou)
});

Módulo 4 de 7

Service Worker e cache

Aqui está a mágica do PWA: um funcionário invisível que guarda os arquivos do app no seu aparelho e entrega tudo mesmo quando a internet some.

O que você vai aprender neste módulo
  • O que é cache e por que ele deixa tudo mais rápido.
  • O que é um Service Worker e como ele "nasce", "trabalha" e é "substituído".
  • As três estratégias de cache mais usadas.
  • Como ver e testar tudo isso funcionando.

O que é cache?

Cache é um lugar onde guardamos uma cópia de algo para não precisar buscar de novo. Quando você abre um site, o navegador baixa imagens, estilos e códigos. Se ele guardar uma cópia no aparelho, da próxima vez abre muito mais rápido, e até sem internet.

🏠 Analogia: a geladeira e o mercado Se você precisa de leite, pode ir ao mercado toda vez (a internet: demora e depende de estar aberto) ou manter uma caixa na geladeira (o cache: está ali, na hora). O segredo é decidir quando usar a geladeira e quando ir ao mercado. Essa decisão é a "estratégia de cache".

O que é um Service Worker?

O Service Worker ("trabalhador de serviço") é um pequeno arquivo JavaScript que o navegador mantém rodando em segundo plano, separado da página. Ele fica entre o app e a internet e vê todos os pedidos de arquivos que o app faz. Para cada pedido ele pode decidir: "entrego a cópia guardada" ou "busco na internet".

Retomando a analogia do restaurante do Módulo 1: o Service Worker é um funcionário na porta da cozinha. Quando o garçom (internet) falha, ele ainda serve o prato que já deixou pronto na geladeira.

⚠️ Duas regras importantes O Service Worker só funciona em HTTPS (ou localhost), e ele não consegue mexer diretamente nos elementos da página: a comunicação entre os dois é feita por mensagens.

O ciclo de vida: como o Service Worker "nasce" e "trabalha"

Ele passa por etapas, como um funcionário novo:

  1. register (registro): a página pede ao navegador: "contrate este arquivo, sw.js, como Service Worker". É o contrato.
  2. install (instalação): o funcionário recebe o treinamento. Aqui ele baixa e guarda no cache os arquivos essenciais do app, o chamado App Shell (a "casca" do app: HTML, CSS, JS e ícones).
  3. waiting (espera): se já existe um funcionário trabalhando, o novato espera na fila até o antigo sair. Veremos isso no módulo de atualização.
  4. activate (ativação): começa a trabalhar. Aproveita para jogar fora o cache de versões velhas.
  5. fetch (atendimento): a partir daí, cada pedido de arquivo passa por ele.

O código, com tudo explicado

Não se assuste: leia os comentários (as linhas que começam com //) como se fossem uma narração. Palavras que você vai ver: .then(...) quer dizer "e depois disso, faça..."; async/await é outra forma de dizer "espere isso terminar".

// ETAPA INSTALL: roda uma vez, quando o Service Worker é baixado.
self.addEventListener('install', (evento) => {
  evento.waitUntil(                      // "espere terminar antes de seguir"
    caches.open('meu-cache-v1')          // abre (ou cria) uma gaveta chamada 'meu-cache-v1'
      .then((cache) => cache.addAll([    // e DEPOIS disso, baixa e guarda estes arquivos:
        './', './index.html', './app.js'
      ]))
  );
});

// ETAPA ACTIVATE: roda quando ele começa a trabalhar.
self.addEventListener('activate', (evento) => {
  // limparCachesAntigos() é uma função de exemplo que apagaria as gavetas de versões antigas
  evento.waitUntil(limparCachesAntigos());
});

// ETAPA FETCH: roda a CADA pedido de arquivo feito pela página.
self.addEventListener('fetch', (evento) => {
  evento.respondWith(                    // "eu respondo por você"
    caches.match(evento.request)         // procura o arquivo na geladeira
      .then((guardado) => guardado || fetch(evento.request))
      // achou? usa a cópia. Não achou? vai buscar na internet.
  );
});

As três estratégias de cache

Cache First
"Geladeira primeiro"

Olha primeiro no cache; só vai à internet se não achar. É a mais rápida. Boa para arquivos que quase não mudam: estilos, scripts, ícones.

Network First
"Mercado primeiro"

Tenta a internet; se falhar (você está offline), usa o cache. Boa para conteúdo que precisa estar sempre atualizado, como a própria página principal.

Stale-While-Revalidate
"Usa já, renova depois"

Entrega na hora o que tem guardado e, ao mesmo tempo, busca uma versão nova para a próxima vez. Equilibra rapidez e atualidade. (Stale = velho; revalidate = conferir de novo.)

Parte 2: testar as estratégias

Aqui você faz uma requisição de mentirinha, e o Service Worker responde de verdade. O resultado diz quem respondeu (cache ou "rede") e quanto tempo levou.

Nenhuma requisição feita ainda.

Experimentos para fazer, em ordem:

  1. Escolha Cache First e clique em "Fazer requisição". Na 1ª vez a resposta vem da "rede" e é guardada. Veja o novo arquivo na lista de cache.
  2. Clique de novo. Agora vem do cache, e o tempo cai, porque não houve espera.
  3. Troque para Network First, marque "Simular internet fora do ar" e faça a requisição. Ela vai tentar a rede, falhar e usar o cache, se houver cópia daquele nome. Se não houver, dará erro 504: "sem rede e sem cópia".
  4. Troque para Stale-While-Revalidate e repita a requisição. Veja que a resposta vem do cache, mas diz que está revalidando em segundo plano.
⚠️ "Limpar todo o cache" apaga a geladeira inteira O app volta a funcionar normalmente enquanto houver internet, e os arquivos vão sendo guardados de novo. Mas, sem internet, ele não abrirá até você recarregar a página online uma vez.
Resumo do módulo
  • Cache é uma cópia guardada para abrir mais rápido e funcionar offline.
  • O Service Worker é um script em segundo plano que decide o que vem do cache e o que vem da internet.
  • Ciclo de vida: register → install → (waiting) → activate → fetch.
  • Estratégias: Cache First (rápida), Network First (atualizada) e Stale-While-Revalidate (as duas coisas).

Módulo 5 de 7

Recursos do aparelho

Um PWA pode guardar dados, abrir a tela de compartilhar do celular e enviar avisos. Tudo isso com permissão da pessoa.

O que você vai aprender neste módulo
  • O que é uma API do navegador.
  • Onde guardar dados: localStorage, IndexedDB e CacheStorage.
  • Como usar o compartilhamento nativo.
  • Como funcionam as notificações e as permissões.

O que é uma API?

API é uma "tomada" que o navegador oferece ao seu código: um conjunto de comandos prontos para pedir coisas ao aparelho, como "compartilhe isto" ou "guarde aquilo". Você não precisa saber como o celular faz; só pede.

Onde guardar dados no aparelho

NomeComo imaginarQuando usar
localStorageUm caderninho de bolsoPequenas preferências em texto: tema escuro, apelido, progresso.
IndexedDBUm arquivo com gavetas organizadasMuitos dados estruturados: listas, anotações, registros.
CacheStorageA geladeira do Service WorkerCópias de arquivos para funcionar offline (Módulo 4).
⚠️ Cuidado Esses dados ficam só naquele navegador, naquele aparelho. Se a pessoa limpar os dados do site, eles somem. E nunca guarde senhas ou dados sensíveis ali. 
// Guardar: setItem('nome-da-gaveta', 'valor em texto')
localStorage.setItem('apelido', 'Ana');

// Ler de volta: getItem('nome-da-gaveta')
const apelido = localStorage.getItem('apelido');   // "Ana"

// Listas viram texto com JSON.stringify e voltam com JSON.parse
localStorage.setItem('feitos', JSON.stringify(['modulo-1', 'modulo-2']));
const feitos = JSON.parse(localStorage.getItem('feitos'));

Compartilhamento nativo (Web Share API)

Sabe aquela janela do celular com os ícones de WhatsApp, e-mail, Telegram e outros? Com a Web Share API o seu app pode abri-la com um link ou texto já preenchido. Funciona melhor em celulares, e só depois de um clique da pessoa (o navegador não deixa "disparar sozinho").

// Primeiro, confere se o navegador sabe compartilhar
if (navigator.share) {
  await navigator.share({
    title: 'PWA Brasil (PT-BR)',            // título
    text: 'Aprenda a criar PWAs!',          // mensagem
    url: location.href                       // o link atual
  });
}

Notificações e permissões

Uma notificação é um aviso que aparece fora do app, no canto da tela. Como pode ser incômodo, o navegador exige permissão da pessoa. A permissão tem três estados: default (ainda não perguntado), granted (concedida) e denied (negada).

💡 Boas práticas Peça permissão só depois de um clique, e explique antes por que você quer enviar avisos. Quem recebe um pedido surpresa na hora em que abre o site costuma negar, e é difícil reverter.

Neste curso mostramos notificações locais: o app mesmo cria o aviso. Para avisar com o app fechado (como o aviso de nova mensagem), é preciso a Push API e um servidor, assunto para um estudo mais avançado.

// Pede permissão (só depois de um clique!)
const permissao = await Notification.requestPermission();

if (permissao === 'granted') {
  // "ready" = espere o Service Worker estar pronto
  const registro = await navigator.serviceWorker.ready;
  registro.showNotification('Olá!', { body: 'Este aviso foi criado pelo app.' });
}

Módulo 6 de 7

Testar, atualizar e publicar

Seu PWA existe, mas como saber se está bom? Como entregar uma versão nova sem quebrar nada? E como colocá-lo na internet para todo mundo usar?

O que você vai aprender neste módulo
  • Como medir a qualidade do app com o Lighthouse.
  • Como funciona a atualização de versão.
  • Como publicar de graça no GitHub Pages.
  • Como testar no seu próprio computador.

Como testar: o DevTools e o Lighthouse

O DevTools (ferramentas do desenvolvedor) é o painel que já vem dentro do navegador. Para abri-lo, aperte F12 ou clique com o botão direito e escolha Inspecionar. Duas abas valem ouro:

  • Application (Aplicativo): mostra o manifest, o Service Worker e o conteúdo do cache. É o "raio-x" do PWA.
  • Lighthouse: um inspetor automático que analisa a página e dá notas de 0 a 100 em desempenho, acessibilidade, boas práticas e SEO (facilidade de ser encontrado em buscas), com dicas do que melhorar.
  1. Abra o app no Chrome e aperte F12.
  2. Clique na aba Lighthouse.
  3. Marque as categorias e clique em Analisar.
  4. Leia as sugestões. Cada uma explica o problema e como corrigir.
  5. Depois, abra a aba Application e confira Manifest, Service Workers e Cache Storage.

As versões mais novas do Lighthouse não têm mais uma categoria chamada "PWA"; as mesmas verificações aparecem na aba Application, na seção do manifest e da instalabilidade. Os nomes dos botões podem variar um pouco entre versões do navegador.

Como funciona a atualização

🏠 Analogia: a nova edição do livro Imagine que o seu aluno tem a 1ª edição de um livro. Você lançou a 2ª. O navegador percebe a mudança, baixa a nova edição em silêncio e a deixa na fila. Quem decide quando trocar? Você, no código: pode trocar na hora ou perguntar antes à pessoa, com um aviso.

Tecnicamente, o navegador confere o sw.js a cada visita. Se o arquivo mudou, ele instala o novo Service Worker, que fica no estado waiting (esperando). O app então mostra o banner "Nova versão disponível". Quando a pessoa clica em "Atualizar agora", o app manda uma mensagem ao novo Service Worker, que "fura a fila" (o skipWaiting) e assume o trabalho. Em seguida a página recarrega para usar os arquivos novos.

// ===== No app.js (a página) =====
// "Quando o navegador achar uma versão nova do Service Worker..."
registro.addEventListener('updatefound', () => {
  const novo = registro.installing;                // o novato que está sendo instalado
  novo.addEventListener('statechange', () => {     // "...e quando ele mudar de etapa:"
    // "installed" e já existe um antigo trabalhando = há versão nova esperando
    if (novo.state === 'installed' && navigator.serviceWorker.controller) {
      mostrarBanner();                               // avisa a pessoa
    }
  });
});

// Quando a pessoa clica em "Atualizar agora", mandamos uma mensagem ao novato
botaoAtualizar.onclick = () => registro.waiting.postMessage({ tipo: 'PULAR_ESPERA' });

// Quando o novato assumir o controle, recarregamos a página
navigator.serviceWorker.addEventListener('controllerchange', () => location.reload());

// ===== No sw.js (o Service Worker) =====
self.addEventListener('message', (e) => {
  if (e.data.tipo === 'PULAR_ESPERA') self.skipWaiting();   // "furar a fila"
});
💡 Dica: como o navegador percebe a mudança? Ele compara o sw.js do servidor com o que já tem, letra por letra. Por isso, mude a constante VERSAO dentro do sw.js toda vez que publicar mudanças: é o jeito mais simples de garantir que o aviso apareça.

Testando no seu computador

Para testar o PWA antes de publicar, você precisa de um servidor local: um programa que "serve" os arquivos da sua pasta pelo endereço localhost.

⚠️ Por que não basta dar dois cliques no index.html? Quando você abre o arquivo direto, o endereço começa com file://, que não é HTTPS nem localhost. Aí o navegador bloqueia o Service Worker.

Duas formas fáceis:

  • Com Python (se instalado): abra o terminal dentro da pasta do projeto e digite o comando abaixo. Depois acesse http://localhost:8080 no navegador.
  • Com o Visual Studio Code: instale a extensão gratuita Live Server, clique com o botão direito no index.html e escolha Open with Live Server.
python3 -m http.server 8080

Publicando de graça no GitHub Pages

Publicar é colocar seus arquivos em um servidor na internet. O GitHub Pages faz isso de graça e já entrega com HTTPS.

  1. Crie uma conta gratuita em github.com.
  2. Clique no + no alto da página e em New repository. Dê um nome (ex.: meu-pwa), deixe como Public e crie.
  3. Na página do repositório, clique em uploading an existing file e arraste todos os arquivos do seu projeto de uma vez (neste curso eles ficam soltos, sem subpastas, o que deixa o envio pelo navegador bem simples). Clique em Commit changes.
  4. Vá em Settings → Pages. Em Source escolha Deploy from a branch, depois a branch main e a pasta / (root), e clique em Save.
  5. Espere 1 a 2 minutos. O endereço do seu app aparece na própria página, no formato https://seu-usuario.github.io/meu-pwa/.
💡 Por que os caminhos deste projeto são "relativos"? Repare que escrevemos ./sw.js e icon-192.png, e não /sw.js. O endereço do GitHub Pages tem o nome do repositório no meio (/meu-pwa/), e caminhos relativos funcionam em qualquer pasta.

Passo 5: o sw.js (Service Worker)

Esta é uma versão curta e simples: guarda os arquivos na instalação e depois responde com o cache primeiro (a estratégia Cache First do Módulo 4).

// Nome do cache. Se mudar os arquivos, troque para v2, v3...
const CACHE = 'meu-pwa-v1';

// Lista dos arquivos que o app precisa para abrir offline
const ARQUIVOS = ['./', './index.html', './manifest.webmanifest', './icon-192.png', './icon-512.png'];

// INSTALL: guarda os arquivos na "geladeira"
self.addEventListener('install', (evento) => {
  evento.waitUntil(caches.open(CACHE).then((cache) => cache.addAll(ARQUIVOS)));
  self.skipWaiting();   // neste exemplo simples, já assume o trabalho
});

// ACTIVATE: joga fora caches de versões antigas
self.addEventListener('activate', (evento) => {
  evento.waitUntil(
    caches.keys().then((nomes) =>
      Promise.all(nomes.filter((nome) => nome !== CACHE).map((nome) => caches.delete(nome)))
    )
  );
  self.clients.claim();   // assume as abas que já estão abertas
});

// FETCH: usa o cache primeiro; se não achar, busca na internet
self.addEventListener('fetch', (evento) => {
  evento.respondWith(
    caches.match(evento.request).then((guardado) => guardado || fetch(evento.request))
  );
});

    Glossário

    Palavras que aparecem no curso, explicadas de forma simples. Volte aqui sempre que precisar.

    API
    Conjunto de comandos prontos que um programa oferece para outro usar. Exemplo: a API de compartilhamento do navegador.

    CacheStorage
    O armazenamento do navegador destinado aos caches usados pelo Service Worker.

    Quem faz o pedido. Na web, é o navegador.

    Anotação no código para pessoas lerem, que o computador ignora.
    CSS
    Linguagem que define a aparência da página: cores, tamanhos e posições.

    O "nome" de um site, como exemplo.com.br.
    Evento
    Algo que acontece (clique, internet que cai, instalação possível) e sobre o qual o código pode ser avisado.
    Extensão (de arquivo)
    O final do nome do arquivo, depois do ponto (.html, .png), que indica o tipo.
    HTML
    Linguagem de marcação que define a estrutura e o conteúdo de uma página.
    HTTP / HTTPS
    A "língua" em que navegador e servidor conversam. O HTTPS é a versão protegida (criptografada), com cadeado.
    IndexedDB
    Banco de dados dentro do navegador, para guardar muitas informações organizadas.
    Instalar (um PWA)
    Colocar o ícone do app na tela inicial para abri-lo como um aplicativo comum.
    JavaScript
    Linguagem de programação que dá comportamento à página: reagir a cliques, guardar dados, conversar com o Service Worker.
    JSON
    Formato de texto para organizar informações em pares "nome: valor". O manifest usa JSON.
    Lighthouse
    Ferramenta do Chrome que analisa uma página e dá notas de qualidade com sugestões.
    localhost
    O endereço do seu próprio computador, usado para testar projetos. O navegador o trata como seguro.
    localStorage
    Pequeno armazenamento de texto do navegador, para guardar preferências simples.
    Manifest
    Arquivo JSON com nome, ícones, cores e modo de exibição do app. A "ficha de cadastro".
    Maskable
    Ícone feito com margem de segurança, para o celular poder recortá-lo em círculo ou quadrado sem cortar o desenho.
    Navegador
    Programa para acessar sites: Chrome, Edge, Firefox, Safari.
    Notificação
    Aviso que aparece fora do app, no canto da tela. Exige permissão.
    Offline / Online
    Sem internet / com internet.
    Permissão
    Autorização que a pessoa dá (ou nega) para o app usar um recurso, como notificações.
    Publicar (deploy)
    Colocar os arquivos do projeto em um servidor para que todos possam acessar.
    PWA
    Progressive Web App (Aplicativo Web Progressivo): site que pode ser instalado, funciona offline e se comporta como app.
    Requisição e resposta
    O pedido que o navegador faz ao servidor e o que o servidor devolve.
    Scope (escopo)
    A área do site que pertence ao app. Links fora dela abrem no navegador.
    Servidor
    Computador sempre ligado que guarda os arquivos de um site e os entrega a quem pedir.
    Service Worker
    Script que roda em segundo plano, entre o app e a internet, decidindo o que vem do cache e o que vem da rede.
    skipWaiting
    Comando que faz um Service Worker novo assumir o trabalho sem esperar na fila.
    Tag
    Marcação do HTML entre < e >, como <p> (parágrafo).
    URL
    O endereço completo de uma página, como https://exemplo.com.br/aula.html.

    Recurso que abre a janela de compartilhamento do aparelho.
